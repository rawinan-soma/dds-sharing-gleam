# Lustre's rendering options, judged against DDS Sharing's three surfaces

- **Question:** What can Lustre do, and at what cost, for this service's three surfaces (Requester form, Reviewer surface, server-rendered collection/expiry pages)? Covers SPA + JSON API with state-transfer hydration, `element.to_string` SSR, server components, `modem` routing, forms and validation, a page with no client bundle (ADR 0018's `/d/<token>`, ADR 0003's collection path), and the options for translated copy (ADR 0010).
- **Issue:** rawinan-soma/dds-sharing-gleam#5 (map #1)
- **Date:** 2026-10-21
- **Primary sources:** Lustre source and guides at tag `v5.7.1` (`github.com/lustre-labs/lustre`, `pages/guide/*`, `src/**`, `CHANGELOG.md`, `pages/announcements/*`); `modem`, `rsvp`, `lustre_dev_tools` (`github.com/lustre-labs/dev-tools`), `formal`, `g18n`/`g18n_dev` source and READMEs at their default branch on 2026-10-21; Hex API (`hex.pm/api/packages/<name>`) for versions; the pilot at `33a9491` (`apps/web/src/**`, `apps/api/src/delivery/pages.ts`, `apps/api/src/i18n/copy-catalogue.ts`); `docs/spec.md` §10, §16, §17.4; ADRs 0003, 0010, 0018. ⚠️ marks what was not verified.

## Answer

**Build the full-stack guide's shape: two Lustre SPA entry points (Requester, Reviewer) on a wisp/mist server, with every page document rendered by the server using `lustre/element`. Use state transfer (JSON in a `<script>`) to send each SPA its first data. Render `/d/<token>` and `/link-expired` server-side with no client script. Do not use server components.** Generate the copy as a typed Gleam module in `shared`, built from the existing `messages/{en,th}.json`.

| Surface | Recommended | Cost | Rejected, and why |
|---|---|---|---|
| **Requester** (`/`, `/submitted`) | Client SPA (`lustre.application`). The server renders the HTML shell with the reference data (disease groups, provinces) embedded as JSON, so there is no `GET /api/reference` round trip. | Date picker, region map and focus management need small JS FFI effects (`effect.before_paint`/`after_paint`). Thai Buddhist-era date formatting moves from `Intl` to Gleam (see Gaps). | Server components: each keystroke and calendar click becomes a round trip over a WebSocket through the ministry edge (see below). Pre-rendering the form: ADR 0003's "picture of a form" argument still applies. |
| **Reviewer** (`/reviewer/...`) | Client SPA, a **separate entry module** in the same `client` build. The server embeds the session (`signed in?`, `mustChangePassword`) as JSON so the route guard needs no first `/session` call. `modem` handles routing. | You write a session-expiry interceptor yourself: wrap `rsvp` handlers so a 401 maps to `SessionEnded`. CSRF double-submit means adding the header with `rsvp.send` and a built request. The dialog focus trap, tab keyboard handling and timers become FFI and effects. | Server components look tempting (few users, server-side data, desktop-only). They are rejected because interactive use **requires a WebSocket**, and §17.4 forbids depending on edge settings. |
| **Collection / expiry** (`/d/<token>`, `/link-expired`) | Plain wisp handler returning `element.to_document_string(view)`, with no `<script>`. | None beyond writing the view in Lustre's HTML DSL. The pilot's hand-rolled template strings port almost one to one. | Anything that hydrates: ADR 0003's guarantee is that collection works when a front-end asset fails. |

**The one-line version:** Lustre fits all three surfaces. Use client SPAs for the Requester and Reviewer and plain `to_document_string` for the two collection pages, with no server components. Copy comes from a typed module generated into `shared` from `messages/*.json`, so a key missing from the served locale fails the build.

## What Lustre offers (v5.7.1, current)

Versions on Hex, 2026-10-21: `lustre` 5.7.1 (2026-07-13), `lustre_dev_tools` 2.4.0 (2026-09-22), `modem` 2.1.3, `rsvp` 2.0.x, `wisp` 2.2.2, `mist` 6.0.3, `formal` 3.0.1, `plinth` 0.11.0, `gleam_json` 3.1.0.

### 1. SPA + JSON API + state-transfer hydration (the full-stack guide)

- The guide uses **three Gleam projects**, `client` (JS target), `server` (Erlang), and `shared`. The reason given is that Gleam "isn't designed to support a single codebase with different applications for different targets" (`pages/guide/06-full-stack-applications.md`, "Project structure").
- **State transfer** in the guide: the server renders a document whose `<div id="app">` is **empty** and adds a `<script type="application/json" id="model">` holding the encoded initial data. The client reads it (via `plinth`), decodes it with the decoder from `shared`, and passes it to `lustre.start(app, "#app", flags)` (guide 06, "Adding hydration"). So the guide's "hydration" is **state transfer, not pre-rendering**: there is nothing to hydrate, only data to start from.
- **True hydration** is also available. `lustre.start` **virtualises whatever DOM is already inside the mount node** and diffs the first `view` against it (`src/lustre/runtime/client/runtime.ffi.mjs:94-96`, `src/lustre/vdom/virtualise.ffi.mjs`). Since 5.5.0, server-rendered `fragment`/`map`/`memo` carry comment markers so virtualisation is exact (`pages/announcements/2026-01-10.md`, "Better virtualisation"). 5.7.0 fixed virtualising HTML from non-Lustre sources (`CHANGELOG.md`). Guide 05 notes that "Lustre doesn't have a built-in hydration mechanism": you must make the client's initial model equal the one the server rendered with (`pages/guide/05-server-side-rendering.md`, "Hydration").
- **Cost of true hydration here:** to render the SPA's `view` on the BEAM, the view code and everything it imports must compile for **both** targets. In practice that means it lives in `shared` with no `plinth`/FFI imports. ADR 0003 already argued against pre-rendering the form, so **state transfer without pre-render** is the shape to copy. It removes a request (the reference data, the session probe) at no hydration risk.
- **Bundling:** `gleam run -m lustre/dev build` uses **bun** and can run the **Tailwind standalone CLI**. Both are downloaded per project into `.lustre/` on first run unless pointed at a local path or `$PATH` (`dev-tools/README.md`, "External binaries"; `src/lustre_dev_tools/bin/bun.gleam`). It accepts **several entry modules** and emits one bundle per entry **plus a shared-code bundle** (`src/lustre/dev.gleam:33-51`). This is the Lustre equivalent of the pilot's lazy-loaded Reviewer chunk (`apps/web/src/app/app.routes.ts`): one build, two entries. It is not ADR 0003's rejected "two builds", because nothing can be released out of step. `--minify` and `--outdir=../server/priv/static` put the bundles where wisp's `serve_static` serves them (guide 06, "Building for production"). With several entries no `index.html` is generated, which is fine because the server writes the documents.
- **Dev loop:** `gleam run -m lustre/dev start` with `[tools.lustre.dev] proxy = { from = "/api", to = "http://localhost:3000/api" }` avoids CORS (guide 06, "Using the development server").

### 2. Server-side rendering with `element.to_string`

- `lustre/element` exposes `to_string`, `to_document_string` (prepends `<!doctype html>`), `to_string_tree`, `to_document_string_tree` and `to_readable_string` (`src/lustre/element.gleam:285-379`). These render **any** `Element`, and no runtime is involved: "we _don't_ need anything from the main `lustre` module" (guide 05).
- Text is escaped. `element.unsafe_raw_html` exists for the rare raw case (`element.gleam:207`). The pilot's `withPhone` splice (`pages.ts`) is better written as `[text(before), strong([], [text(phone)]), text(after)]`.
- This is exactly the `/d/<token>` and `/link-expired` case: a wisp handler does `view(data) |> element.to_document_string |> wisp.html_response(200)` (guide 06 `serve_index`). The pilot's pages are already "plain, semantic HTML rather than a templating engine" with an inlined `<style>` (`apps/api/src/delivery/pages.ts`), so the port is mechanical. The same mechanism renders the **four emails' HTML** on the server.

### 3. Server components

- A server component runs `init/update/view` **on the server**. A client runtime (~14 KB minified, `priv/static/lustre-server-component.min.mjs`) applies DOM patches and sends events back (`src/lustre/server_component.gleam` module doc). Started with `lustre.start_server_component`, `lustre.supervised` or `lustre.factory` (`src/lustre.gleam:389-436`). You wire the transport to the runtime yourself (`register_subject` / `register_callback`).
- **Transports:** `WebSocket` (default), `ServerSentEvents`, `Polling` (`server_component.gleam`, `TransportMethod`). The module doc calls SSE and polling "unidirectional". In the inlined client runtime the SSE and polling classes have an empty `send(e){}` (`server_component.gleam`, `script()` body). So **without a WebSocket, DOM events never reach the server**, and an interactive server component needs a WebSocket.
- The component renders into a **shadow root** and clears it on mount. Page stylesheets are adopted into it (`script()` body: `attachShadow`, `adoptedStyleSheets`). 5.7.0 added CSRF tokens on the connection URL (`<meta name="csrf-token">` or `server_component.csrf_token`) (`CHANGELOG.md` v5.7.0; `pages/announcements/2026-05-06.md`).
- **Fit:** poor on every surface. §17.4 makes "no setting on a proxy this project does not administer … a precondition", and WebSocket upgrade through the ministry edge is such a setting (⚠️ whether the edge passes `Upgrade` is unknown). It also needs JS, so it cannot serve `/d/<token>`. Every input event on the Requester form would be a network round trip. It also adds a per-client server process and reconnection behaviour (the client retries with backoff up to 10 s) for no gain: the Reviewer's data needs are request/response, and the queue deliberately **does not auto-refresh** (§10.1). Keep it in reserve only if a live-updating view is ever wanted.

### 4. Client routing with `modem`

- `modem` "isn't a router, but it can help you build one". `modem.initial_uri()` gives the first URL, `modem.init(on_url_change)` subscribes, and `push`/`replace`/`load`/`back`/`forward` are effects (`modem/README.md`; `src/modem.gleam`). Routing is a `case uri.path_segments(uri.path)` in `update`. The pilot's nested Angular routes (`reviewer.routes.ts`: shell → queue → `alerts/:id` | `in-flight/:id` | `lookup/:reference` | `:id`) become a `Route` custom type plus a parse function.
- **Guards** (`requireSession`, `requirePendingChange`) become a check in the route-change branch of `update` that answers with `modem.replace(sign_in_uri)`. With the session in the state-transferred JSON, no async `ensureReady()` is needed on first load.
- **Gotcha:** `modem.init` intercepts **every same-origin `<a>` click** unless it has `target="_blank"` or `download` (`src/modem.ffi.mjs:33-50`). Any SPA link to a server-only route (e.g. `/link-expired`, a future `/api/...` download) must use `download`, `target`, or `modem.load`, or use `modem.advanced` to turn off internal-link handling. Today the SPA does not link to `/d/...`, so this is a rule to remember, not a blocker.

### 5. Forms and validation

- `event.on_submit(fn(List(#(String, String))) -> msg)` gives the form's name/value pairs and calls `prevent_default`. Files are excluded (`src/lustre/event.gleam:301-325`). Per-field `on_input`/`on_change`/`on_check` support controlled inputs (`event.gleam:268-294`; `pages/hints/controlled-vs-uncontrolled-inputs.md`).
- **`formal` 3.0.1** is pure Gleam (deps: `gleam_stdlib`, `gleam_time`; no target restriction, `formal/gleam.toml`). One form definition can therefore live in `shared` and run in the browser and in the wisp handler. Its error text comes from a **pluggable translator** `fn(FieldError) -> String` set with `form.language` (default `en_gb`) (`src/formal/form.gleam:19,115-131,1076`), so Thai messages can come from the catalogue.
- **Fit with the pilot:** the pilot does not validate formats. Contact fields only need to be present (`request-form.ts`, §4.7), and the real rules are cross-field: 365-day span, reversed range, before 1 Jan 2567, area mode. These are a pure `problems_of(FormState)` function that ports as is into `shared`. The live requirement checklist (`met`/`unmet`/`broken`) needs a model updated on every input, not a submit-time decoder. So use **controlled inputs plus a shared `problems_of`**, and use `formal` (or plain decoders) only for the server's JSON/body parse. The server stays authoritative, as today with 400 `{errors:[...]}` and 409 for in-progress (`requester-api.ts`).

### 6. A server-rendered page with no client bundle (ADR 0018, ADR 0003)

- Fully supported, and the simplest thing Lustre does: §2 above. The `server` project imports `lustre` only for `lustre/element` and `lustre/element/html`. No runtime starts and no `<script>` is emitted unless you write one.
- ADR 0003's guarantee holds structurally: the `/d/<token>` handler is a wisp route outside the SPA catch-all, and the archive route streams from wisp. The SPA's catch-all must exclude `/d/`, `/api/`, `/health` and `/static/`, just as NestJS excludes the API prefix today.
- Styling: the pilot inlines the design tokens into a `<style>` because these pages "cannot share the SPA's stylesheet" (`pages.ts`). In the Gleam app the tokens can be one Gleam constant in `shared` used by both the inlined style and the SPA's CSS, or the pages can `<link>` the SPA's CSS file. ⚠️ Linking reintroduces an asset dependency for *styling* only. The button is still a plain `<a href=".../archive">`, so collection still works if the CSS fails.

## Translated copy (ADR 0010)

The constraints from ADR 0010 / §16.3: `messages/en.json` and `messages/th.json` stay the reviewed source of truth. Only Thai is served, with no URL strategy. One catalogue covers SPA screens, server pages and the four emails. A missing key must not leak a raw key to a Requester. Today: **416 keys, flat `key → string`, 50 with `{param}` placeholders, no plurals or selectors** (counted from `messages/en.json`). Paraglide has no Gleam output, and the pilot's server side already bypasses it with a 60-line JSON reader (`apps/api/src/i18n/copy-catalogue.ts`).

| Option | What it is | Missing-key behaviour | Fit |
|---|---|---|---|
| **A. Generated typed module (recommended)** | A small Gleam codegen script (in `shared/dev`, run before build) reads `project.inlang/settings.json` and `messages/<locale>.json`. It emits `shared/copy.gleam` with one function per key for the served locale, e.g. `pub fn requester_collect_reference(reference reference: String) -> String`. The same module compiles for both targets. | **Compile-time error** at every call site if the key is gone. The generator **fails** if the served locale lacks a key that the base/English file has, so ADR 0010's "raw key on screen" failure becomes impossible rather than gated. | Best. It keeps the JSON files as the document people review (§16.3 rejected a "hand-rolled typed module" only because the *source* stopped being a document; here the module is generated, not the source). It is Paraglide's model (a compiled function per message) without the Angular/Node gap, and it is about a day of work for 416 flat strings. |
| B. `g18n` 4.0.0 + `g18n_dev` 2.0.0 | Runtime translator. `g18n_dev generate` turns flat JSON into a `translations.gleam` holding per-locale translators; lookups are `g18n.translate(t, "key")` (`g18n-dev/README.md`, "Generated Output"). Has a `check` command for CI. | Lookups by **string key**, so a typo or missing key is a runtime fallback, not a compile error (⚠️ exact fallback not read). | Workable but weaker than A. Thai is not among its 12 languages for plurals/dates (`g18n/README.md`). It expects files under `src/<project>/translations/`, not `messages/`. |
| C. `kielet` 4.0.2 | GNU gettext (`.po`/`.mo`) for Gleam (Hex metadata). | gettext returns the msgid. | Would replace the inlang JSON format. That contradicts ADR 0010's choice of files, so it would need a new ADR. |
| D. `dachshund` 0.1.1 | "Translations as code, inspired by Paraglide" (Hex metadata). ~100 recent downloads. | ⚠️ not read. | Too young to depend on. |
| E. Port the pilot's runtime reader | Read the JSON at server start and embed the served catalogue in the SPA (state transfer or a build-time JSON import). | Runtime throw (server) or raw key (client). | Simplest, but it gives up compile-time checking that Gleam offers for free. |

ADR 0010's other rules carry over unchanged under A. No `url` strategy is needed, because a generated module serving one locale has no notion of a URL locale. Locale selection becomes a build-time or config choice (`en` in dev, `th` for production). §17.1's parity check between `en.json` and `th.json` becomes part of the generator.

## Gaps and costs to carry into the build tickets

1. **Thai date formatting has no `Intl` on the BEAM.** The pilot formats Buddhist-era dates with `Intl.DateTimeFormat('th-TH-u-ca-buddhist')` on both sides (`apps/web/src/app/requester/be-date.ts`, `apps/api/src/i18n/ask-copy.ts`). Emails and server pages render on Erlang, so a **pure-Gleam formatter in `shared`** is needed: Thai month names, year + 543, Asia/Bangkok offset. It is small, but it is new code where the pilot used a platform API. The client may keep `Intl` via FFI only if its output is tested equal to the shared formatter.
2. **Browser-API code becomes FFI.** Focus moves (`dialog.ts` focus trap, `afterNextRender(...focus())` in sign-in/password/dossier), roving tabindex (`segmented`, `region-map`, queue tabs), `setInterval` staleness tick (`queue.page.ts`) and session warn/end timers (`reviewer-session.ts`) all need `effect.from` / `effect.after_paint` with small `.mjs` FFI or `plinth`. Lustre has no focus helper. ⚠️ `plinth` coverage of each API was not checked.
3. **No HTTP interceptor.** Angular's `reviewerSessionInterceptor` and `withXsrfConfiguration` (`app.config.ts`, `session-interceptor.ts`) have no `rsvp` equivalent. Write one `reviewer_api.send` helper in the client that adds `X-CSRF-Token` from the cookie and maps 401 `session_expired|unauthenticated` to a message.
4. **No lazy loading, but multiple entries.** The Reviewer code stays out of the Requester's download only if the Reviewer is its own entry module (§1). Pages are then fixed per entry: `/reviewer/*` documents load the Reviewer bundle, everything else loads the Requester bundle.
5. **Build tooling downloads binaries.** bun (and Tailwind if detected) are fetched on first build unless configured to use `$PATH` (`dev-tools/README.md`). This matters for the Docker build and any offline Production build (map: "Production deployability"). Set `no_tailwind = true` if the design stays hand-written CSS.
6. **Drift to raise, not settle:** spec §16.2 and ADR 0003 say `/link-expired` is served "by Angular", but the pilot renders it on the server (`apps/api/src/delivery/link-expired.controller.ts`, `pages.ts` `renderExpiredPage`), consistent with ADR 0018's catalogue note. The port should follow the pilot (server-rendered, no bundle), and the spec table needs a drift ticket per map #1's reference rule.
7. **Testing hooks exist.** `lustre/dev/simulate` and `lustre/dev/query` drive `init/update/view` without a DOM (`src/lustre/dev/*`; fixes in `CHANGELOG.md` v5.7.0), and `modem.simulate`/`rsvp.simulate` plug into them. This is relevant to the open "Testing strategy" question, not decided here.
